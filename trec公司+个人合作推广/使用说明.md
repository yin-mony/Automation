# TREC 公司+个人合作推广使用说明

## 项目用途

本项目用于读取 TREC 已清洗后的全量初始数据表，再按公司模式或个人模式调用 SerpApi Google 搜索接口，并根据 SerpApi 返回的 `organic_results.link` 使用 DP 浏览器打开二级页面，匹配公开的邮箱、电话、Facebook 主页候选链接和来源链接。

当前版本不再默认进入 TREC 网站重新采集，也不再使用浏览器打开 Google 做搜索。搜索统一走 `https://serpapi.com/search?engine=google`，每个搜索对象消耗 1 次 SerpApi 免费额度；二级页面会用 DP 浏览器打开 SerpApi 返回的普通网页链接。

## 当前主流程

1. 程序读取 `file/已获取到的初始总数据.xlsx`。
2. 公司模式筛选有挂靠公司信息的数据，并按公司名去重。
3. 个人模式筛选 Active、无挂靠公司、未来指定月份内到期的数据。
4. 每家公司或每个人调用 1 次 SerpApi 搜索。
5. SerpApi 固定读取 Google 第一页，不传 `num`，按当前页实际返回的自然结果全部处理。
6. 程序读取每条自然结果里的 `link`，用 DP 浏览器打开普通网页二级页面提取邮箱和电话。
7. 邮箱和电话写入结果表前会先清洗：过滤 `admin@`、`info@` 等公共邮箱，过滤 `.gov`、`.mil`、`.edu` 以及军警学校相关域名，只保留更像公司或个人的邮箱。
7. 每完成一个对象都会保存缓存、断点和 Excel 结果表。
8. 结果表、断点和缓存写入 `outputDir`，默认是 `output`。
9. 如开启邮件发送，流程结束后只发送本项目固定的 4 个数据表附件。

## 项目结构

```text
trec公司+个人合作推广/
├─ run.py
├─ main.py
├─ email_util.py
├─ run_config.json
├─ 使用说明.md
├─ 更新说明.md
├─ file/
│  ├─ 初始总量数据未清洗.xlsx
│  ├─ 已获取到的初始总数据.xlsx
│  └─ time2renew-logo.png
└─ output/
   ├─ 已完成搜索匹配的公司联系信息数据.xlsx
   ├─ 已完成搜索匹配的个人联系信息数据.xlsx
   └─ 邮件发送记录.xlsx
```

| 文件 | 作用 |
| --- | --- |
| `run.py` | GUI 窗口入口，只负责配置界面、开始运行按钮和日志展示。 |
| `main.py` | 业务主流程入口，初始化配置、读取清洗表、执行公司/个人模式、调用 SerpApi、抓取二级页面、导出结果和发送邮件。 |
| `email_util.py` | 邮件发送工具，只发送固定的 4 个数据表附件。 |
| `run_config.json` | GUI 保存的本地配置文件；可以删除，删除后使用 `main.py` 默认配置。 |
| `使用说明.md` | 项目说明文档，记录用途、结构、配置和运行建议。 |
| `更新说明.md` | 项目调整记录，说明每次重要改动、影响范围和运行注意事项。 |

## TREC 采集流程说明

旧版 TREC 网站全量采集流程已经在 `main.py` 的 `trecArchive()` 注释中保留，方便以后需要恢复时参考。

当前版本不会自动重新采集 TREC 网站，也不会自动重建清洗表。公司模式和个人模式都基于已存在的清洗表：

```text
file/已获取到的初始总数据.xlsx
```

如果这个文件不存在，程序会停止并提示先准备清洗后的全量初始数据。

## 内置数据和输出文件

`file` 是内置数据文件目录，固定不可改。程序只从这里读取底表，不把搜索结果、断点或缓存写回 `file`。

| 内置数据文件 | 说明 |
| --- | --- |
| `初始总量数据未清洗.xlsx` | TREC 网站全量原始底表，当前版本只作为历史底表和邮件附件保留。 |
| `已获取到的初始总数据.xlsx` | 已清洗全量初始表，当前公司/个人搜索都读取它。 |
| `time2renew-logo.png` | 推广邮件内嵌 Logo，固定由推广邮件流程读取。 |

`outputDir` 是最终输出目录，默认 `output`，可以在 GUI 中修改，但禁止设置为 `file`。

| 输出文件 | 说明 |
| --- | --- |
| `已完成搜索匹配的公司联系信息数据.xlsx` | 公司模式搜索结果表。 |
| `已完成搜索匹配的个人联系信息数据.xlsx` | 个人模式搜索结果表。 |
| `邮件发送记录.xlsx` | 推广邮件后台记录表；未真实发送时也会生成，方便人工复核。 |

运行时还会在 `outputDir` 目录后台生成 SerpApi 专用断点和缓存：

| 文件 | 说明 |
| --- | --- |
| `serpapi_company_search_progress.json` | 公司模式断点，下次从上次完成位置继续。 |
| `serpapi_company_contacts_cache.json` | 公司模式搜索缓存，避免重复消耗额度。 |
| `serpapi_person_search_progress.json` | 个人模式断点，下次从上次完成位置继续。 |
| `serpapi_person_contacts_cache.json` | 个人模式搜索缓存，避免重复消耗额度。 |

这些断点和缓存是程序状态，不需要也不应该放到 GUI 配置里。

## 启动方式

推荐使用 GUI：

```bash
python run.py
```

也可以直接运行主流程：

```bash
python main.py
```

GUI 左侧只有三个入口：配置、公司模式、个人模式。顶部只有一个“开始运行”按钮。配置页只负责保存配置，不直接运行。

## 配置说明

默认配置统一写在 `main.py` 的 `Main.__init__()` 中。`run_config.json` 只是 GUI 上次保存的本地配置，不是必需文件。

| 配置 | 建议 | 说明 |
| --- | --- | --- |
| `isOnline` | 本机调试填 `false` | 只用于运行环境标记和邮件正文，不改变搜索逻辑。 |
| `outputDir` | 默认 `output` | 最终结果表、断点和缓存所在目录；禁止填 `file`。 |
| `sendEmail` | 测试时填 `false` | 开启后流程结束发送固定 4 个表格附件。 |
| `promotionExecuteSend` | 测试时填 `false` | 推广邮件单一开关；`false` 只生成后台发送记录，`true` 才真实发送推广邮件。 |
| `email` | 开启邮件时必填 | 多个邮箱用英文逗号或分号分隔。 |
| `cleanFileName` | 默认即可 | 当前搜索唯一读取的数据表，固定从 `file` 目录读取。 |
| `companyResultFileName` | 默认即可 | 公司模式最终结果表文件名。 |
| `personResultFileName` | 默认即可 | 个人模式最终结果表文件名。 |
| `expireMonths` | 默认 `6` | 个人模式只处理未来多少个月以内到期的数据。 |

以下内容不再作为配置项：

| 项目 | 当前处理方式 |
| --- | --- |
| 公司模式开关、个人模式开关 | GUI 当前按钮就是运行状态，不写入 `Main.__init__()` 默认配置，也不保存到 `run_config.json`。 |
| 公司总上限、个人总上限 | 已取消，不再配置。 |
| 搜索起始位置 | SerpApi 固定 Google 第一页；对象处理位置由后台断点自动接续。 |
| 本次搜索数量 | 程序内部固定每次 10 个对象。 |
| SerpApi 返回结果数 | 不传 `num`，按当前搜索结果页实际返回的自然结果全部处理。 |
| 断点文件、缓存文件 | 公司/个人逻辑内部固定后台保存，不开放配置。 |
| 内置数据目录 | 固定为 `file`，不开放配置，不允许改成输出目录。 |
| 推广邮件主题、正文、签名、Logo | 固定写在 `main.py` 的推广流程函数中，Logo 固定读取 `file/time2renew-logo.png`。 |

SerpApi Key、结果附件 SMTP 授权码、推广邮件 SMTP 授权码不会作为可编辑项写入 GUI，也不会写入 `run_config.json`，更不会以明文提交到远端仓库。正式运行请在系统环境变量中配置：

| 环境变量 | 说明 |
| --- | --- |
| `TREC_SERPAPI_KEY` | SerpApi 搜索接口 Key。 |
| `TREC_RESULT_SMTP_AUTH_CODE` | 最终结果附件通知邮件的 SMTP 授权码。 |
| `TREC_PROMO_SMTP_AUTH_CODE` | 推广邮件真实发送使用的 SMTP 授权码。 |

结果附件发件邮箱、推广发件邮箱和 SMTP 服务器仍由 `main.py` 固定维护，不在 GUI 中开放修改。GUI 只展示推广发件邮箱，不能修改。

本机调试时如果需要“明文可见”的运行方式，请只在本机系统环境变量里明文保存，不要写入代码、说明文档或提交记录。PowerShell 示例：

```powershell
$env:TREC_SERPAPI_KEY = "你的 SerpApi Key"
$env:TREC_RESULT_SMTP_AUTH_CODE = "你的结果附件 SMTP 授权码"
$env:TREC_PROMO_SMTP_AUTH_CODE = "你的推广邮件 SMTP 授权码"
python run.py
```

如需长期保存，请在 Windows 系统环境变量中新增以上 3 个变量。这样程序仍然可以直接运行，但远端仓库不会泄露可用凭证。

## 公司模式

公司模式固定执行以下规则：

1. 读取 `已获取到的初始总数据.xlsx`。
2. 只保留 `状态 = Active` 的数据。
3. 只保留有 `挂靠公司名称` 或 `关联名称` 的数据。
4. 按公司名去重。
5. 搜索词格式为：`"公司名" real estate contact email phone 地区`。
6. SerpApi 返回自然结果后，程序读取每条 `link`。
7. 用 DP 浏览器打开普通网页二级页面，从页面正文里补充提取邮箱和电话。
8. 写入结果表前会过滤公共邮箱、政府/军事/学校域名邮箱和明显占位电话。
8. 导出中文表头的公司结果表。

Facebook、Instagram、LinkedIn、YouTube、Google 等容易登录或风控的平台，只记录候选链接，不强行打开正文。

## 个人模式

个人模式固定执行以下规则：

1. 读取 `已获取到的初始总数据.xlsx`。
2. 只保留 `状态 = Active` 的数据。
3. 只保留没有挂靠公司名称的数据。
4. 只保留未来指定月份内到期的数据，默认 6 个月。
5. 地区不限，地区字段只用于搜索词补充和人工核对。
6. 搜索词格式为：`"姓名" "real estate agent" contact email phone 地区`。
7. SerpApi 返回自然结果后，程序读取每条 `link`。
8. 用 DP 浏览器打开普通网页二级页面，从页面正文里补充提取邮箱和电话。
9. 写入结果表前会过滤公共邮箱、政府/军事/学校域名邮箱和明显占位电话。
9. 导出中文表头的个人结果表。

个人模式不再优先进入 HAR 网站做站内搜索。若 SerpApi 返回 HAR 普通二级链接，程序会用 DP 浏览器打开；如页面出现官方验证，只按页面实际可见文本提取，不自动破解验证。

## 断点续跑

每完成一个搜索对象，程序都会立即保存：

- Excel 结果表
- JSON 缓存
- JSON 断点

下次运行同一个模式时，程序会自动读取断点继续。GUI 不再提供手动起始位置输入框。

如果要从头重新搜索，需要同时删除对应模式的断点文件和缓存文件。只删除断点但保留缓存时，已缓存对象仍会被跳过，避免重复消耗 SerpApi 额度。

## 禁止或不建议

- 不要把模式开关、处理总上限、搜索起始位置、本次数量、SerpApi 返回条数重新加回 GUI 配置。
- 不要把“本次数量”改成用户可填项，当前项目固定每次 10 个对象。
- 不要把 SerpApi 的 `num` 固定写死，当前项目按 Google 当前页实际返回结果处理。
- 不要把 `outputDir` 设置为 `file`，`file` 只能存放内置底表。
- 不要删除 `已获取到的初始总数据.xlsx`，公司模式和个人模式都依赖它。
- 不要把 SerpApi Key、SMTP 授权码等可用凭证明文推送到远端仓库；密钥统一放在本机系统环境变量中。
- 不要把 SerpApi Key、发件邮箱、SMTP 授权码移动到 GUI 让普通用户修改；GUI 只负责业务运行配置。
- 不要把旧版浏览器搜索配置重新加回 `run_config.json`。

## 推荐运行方式

测试公司模式：

```text
模式：公司模式
固定规则：每次 10 家公司
```

测试个人模式：

```text
模式：个人模式
到期月份：6
固定规则：每次 10 位个人
```

正式运行时，保持每次 10 个对象断点续跑即可。这样既方便检查结果，也能控制 SerpApi 免费额度消耗。
