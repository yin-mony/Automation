# 更新说明

## 2026-08-14 · 3.0 规范化重构

### 代码结构

- 按仓库 `docs/NAMING.md` 重构为 `main.py`、`data.py`、`serp.py`、`proxy.py`、`browser.py`、`mail.py` 和 `run.py`。
- 每个 Python 文件只保留一个顶层主类。
- 非 GUI 模块不嵌套异常类或辅助类，流程异常统一使用 Python 内置异常。
- 类名使用 `PascalCase`，方法和变量使用 `camelCase`。
- 项目源码不使用参数、返回值或变量类型注解，并新增自动检查防止回退。
- 删除泛化长模块和重复职责，补充中文 docstring 与关键流程中文注释。
- GUI 入口保持 `run.py`，打包脚本缩短为 `trec.spec`。

### 原业务规则

- 公司继续按 Active 经纪人的挂靠公司去重汇总。
- 个人继续筛选 Active、无挂靠且在到期月份窗口内的数据。
- 每日目标保持 10 个公司和 10 个个人。
- 中文公司、个人结果文件名保持不变。
- 已完成对象通过 SQLite 跳过，缓存命中不重复消耗额度。

### 初始数据

- Texas Open Data 改为官方全量加增量同步。
- 所有状态合并到 `output/data.db`。
- 首次运行自动复制旧 `trec_automation.db`，不删除历史文件。
- 保留旧流程需要的两份中文 TREC Excel 底表。

### SerpApi 免费额度

- 保持 SerpApi 作为 Google 搜索入口。
- 月额度固定 250 次，硬预留 20 次。
- GUI 启动后自动读取官方 Account API，额度显示与 SerpApi 账号实时对齐。
- 每日新搜索固定 6 次；合并模式公司和个人各 3 次。
- 日常搜索预留 180 次，人工复查预留 20 次，另保留 30 次安全余量和 20 次硬预留。
- 新请求不传固定 `num`，使用 Google 第一页默认结果。
- 确定已经响应的解析异常只记账一次且不自动重试。

### 代理与浏览器

- 默认切换为 DrissionPage 直接访问，`proxyRequired=false` 时完全跳过代理读取、检测和桥接。
- 代理实现继续保留为可选能力，手动开启后仍执行多目标检测和出口一致性验证。
- `ipfiy.py` 作为当前本地 SOCKS5 来源，使用 AST 读取，不执行测试代码。
- pproxy 在程序内创建只监听 `127.0.0.1` 的 HTTP 代理桥。
- 上游、代理桥和 DrissionPage 三层验证失败时全部停止，禁止直连回退。
- 上游探测改用 HTTPS 443 端口；上游握手和代理桥出口验证遇到瞬时断开时最多重试 3 次。
- 代理健康检查改为多目标策略：SOCKS5 预检只记录诊断，代理桥实际取得出口 IP 后才放行浏览器。
- 代理只用于 DrissionPage；TREC、SerpApi 和 SMTP 保持直连。
- 普通网页使用固定代理出口和持久浏览器档案；Facebook 不再发起页面请求。

### Facebook

- 只记录 SerpApi 结果或普通网页发现的 Facebook 主页链接。
- Facebook 链接写入数据库、GUI 结果页和公司/个人 Excel 文件。

### GUI 与审核

- 使用 PySide6 重做为紧凑运营工作台。
- 增加工作台、运行设置、任务监控、邮件设置、结果审核、结果数据、连接状态和操作说明八个页面。
- 结果审核支持单选、多选和全选当前筛选结果，并在同一事务中批量更新审核状态。
- 运行设置新增每日新搜索上限数字输入框，可保存到本地配置；工作台和三种模式的额度说明会同步更新。
- 工作台新增五阶段流程状态；运行设置会随公司、个人和合并模式动态更新全部规则。
- SerpApi Key、阿里邮箱账号和授权码集中到 `Main.__init__` 默认参数。
- 增加暂停、继续、安全停止和人工接管状态。
- 邮件默认通过 IMAP 写入阿里邮箱草稿箱，也可单选真实 SMTP 发送并二次确认。
- 邮件正文升级为纯文本和 HTML 双版本，并以内嵌 CID 方式加入 Time2Renew Logo。
- 新增 SQLite `mail_actions` 台账，跨运行跳过重复草稿和重复真实发送。
